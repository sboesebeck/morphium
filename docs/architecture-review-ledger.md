# Architecture review ledger

Scope: architecture review and challenge findings for the `release/7.x` branch.
Severity is the original review rating unless noted. Findings downgraded or
rebutted by the challenge remain here to preserve the review trail.

| Finding | Original severity | Challenge outcome | Evidence / disposition |
|---|---:|---|---|
| Buffered writer reports success before bulk persistence and may lose queued entries on enqueue/flush errors. | HIGH | Confirmed | Built-in bulk contexts now propagate failures and validate write replies; wire bulk commands do not retry lost replies. Failed/ambiguous entries are quarantined outside the active buffer, not automatically retried, and can be inspected and explicitly discarded after application reconciliation through `BufferedMorphiumWriterImpl`. Quarantine is in memory only, not a durable recovery log, and intentionally does not expose captured query/document payloads because they may be mutable or sensitive. Reconciliation correlation is guaranteed only when the caller supplied a unique callback instance per logical write; `UnresolvedWrite.getCallback()` returns that exact instance for identity matching against caller-owned intent. Callers without unique callbacks cannot distinguish otherwise identical writes from the public unresolved-write view; retain the writer reference to inspect entries after close. Third-party bulk contexts must honor the documented execute contract. Tests cover success, enqueue failure, driver execution failure including a possibly applied insert, exact callback correlation, pooled driver exceptions and write-concern errors, and WAIT progress. Explicit buffer overflow discard strategies remain lossy by design. |
| `Morphium.queueTask()` retries all submission exceptions indefinitely and can block forever after close/rejection. | MEDIUM | Confirmed | Replaced the retry loop with explicit lifecycle/rejection failure. A regression test covers submission after close; executor rejection while Morphium remains open is not directly tested. |
| A throwing public shutdown listener aborts the remaining close sequence. | MEDIUM | Confirmed | Listener and resource-cleanup steps are isolated; close attempts writer, driver, cache and final reference cleanup even when an earlier step fails, then logs and throws an aggregate exception with per-step causes. Driver close failures are surfaced and shared-driver registry cleanup still runs. The close gate remains one-shot, so a failed step is reported but is not retried by a later close call. Concurrent close callers are gated so cleanup starts once; later callers may return before the first caller completes. Regression tests cover listener failure, cache-reset failure with cache-close/final cleanup continuing, driver-close failure with later cleanup continuing, and concurrent close. |
| Driver contract is coupled to `Morphium` and wire/concrete types while `Morphium` depends on the driver. | MEDIUM-HIGH | Confirmed, remedy constrained | `MorphiumDriver` is explicitly a public extension SPI ("All drivers need to implement this interface"), and its concrete wire types are part of that signature. Relabeling it internal would be misleading and a neutral-port extraction would change a broad public contract. No API signature change was made; defer extraction to a compatibility-planned change. The new boundary test guards extension-module direction only, not this intra-core coupling. |
| No automated architecture boundary gates. | MEDIUM | Confirmed, partial mitigation | `CoreModuleBoundaryTest` checks selected framework import prefixes in core Java files and three literal extension artifact IDs in the core POM. It does not check fully qualified references, transitive dependencies, parent POMs, or the full module DAG; a comprehensive architecture gate remains open. |
| Static `ClassGraphCache` state and live-scan-only APIs may be unsuitable for native/multiclassloader contexts. | MEDIUM / conditional | Conditional; not a universal defect | Existing Quarkus pre-registration explicitly covers selected annotation-name lookups; metadata and subclass APIs require a live scan. The cache is process-global. Documented this support boundary in the performance guide; no unsupported native-image guarantee is added. Per-classloader scoping is deferred until supported runtime requirements and ownership are defined. |
| Large `Morphium` / `MorphiumBase` classes by LOC. | MEDIUM | Downgraded / monitor | Size alone is not an actionable architectural defect. No refactor solely on LOC; monitor for cohesive, behavior-based extractions. |
| MongoDB synchronous driver and test libraries leak into production dependencies. | MEDIUM | Rebutted | Verified with `mvn -pl morphium-core -DskipExtensions dependency:tree -Dincludes=org.mongodb:mongodb-driver-sync,org.mongodb:mongodb-driver-core`: both resolved dependencies have `test` scope. No change warranted. |
| Documented default driver may not match the implementation default. | LOW | Not in scope | Below the requested severity threshold; recorded for completeness, no change in this slice. |
| Logback / dependency concern raised during challenge. | Unrated / pending verification | Not established as > LOW | No concrete severity-rated finding was available to implement safely; dependency cleanup is out of scope absent a confirmed production-impacting issue. |
