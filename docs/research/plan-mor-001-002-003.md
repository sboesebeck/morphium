## 0. Findings that change the ledger text

1. **Do not expose `ObjectMapperImpl.marshallIfNecessary` on `MorphiumObjectMapper`** (MOR-002 suggests it). It is wrong for update values:
   - Custom-mapped types go through `serialize()` (`ObjectMapperImpl.java:310-312`), which wraps a non-Map result as `{"value": x}` (`:394`) and adds
     `class_name` to Map results (`:391`). A `LocalDate` would become `{value: epochDay}`; `BsonEncoder` writes java.time natively (`BsonEncoder.java` ~`:360-378`).
   - An `Iterable` goes to `serializeIterable(it, null, null)` (`:333-335`); enums then become `{class_name, name}` (`:785-786`, `:920-924`) while today a raw
     `List<Enum>` reaches the encoder as a plain string (`BsonEncoder.java:354-357`).
   - Arrays marshal elements first and then `serializeIterable` (`:318-331`): array elements get no `class_name`, Iterable elements do (`:775-778`).
   - Its only callers are the two aggregators (`AggregatorImpl.java:642`, `InMemAggregator.java:583`). Leave it alone.
2. **Add a new method for update values**, proposed name `marshallUpdateValue(Object)`: a pure walk that rewrites only POJOs and enums.
3. **`getMongoFieldName` cannot be reused for update keys** (`AnnotationAndReflectionHelper.java:331-413`): it throws for unknown fields (`:361-370`), with
   `ignoreUnknownField=true` it rewrites unknown snake_case keys to camelCase (`:363-364`), and it returns keys containing `.`, `(` or `$` unchanged (`:339-343`).
   A lenient resolver is needed: unknown keys pass through (Spring `UpdateMapper` behaviour, other-clients.md pattern 4).
4. **`class_name` is convention-dependent today:** the writer's `marshallIfNecessary` (`MorphiumWriterImpl.java:2733-2783`) always adds `class_name`, also to a single
   value (`:2742`); `store()` writes none for a single non-polymorphic embedded field (`ObjectMapperImpl.java:620-623`) but does for collection elements and map
   values (`:775-778`, `:871-874`). Plan: keep the writer's legacy single-value behaviour; make `findOneAndUpdate` follow `store()`.
5. **Do not reuse `Morphium.simplifyQueryObject` for MOR-003** (`Morphium.java:1047-1065`): it flattens `$and` with `putAll` (`:1055`) and loses predicates with equal keys.
6. **`Query.findOneAndUpdate(Map)` (one argument) has the same hole and swallows errors**: raw map at `Query.java:443`, `MorphiumDriverException` caught with only
   `log.error` (`:456-458`); a POJO there silently returns `null`. The reproduction covered only the 3-argument overload (`:493`). Fix both, do not change the swallowing.
7. Nothing in production code calls `findOneAndUpdate` except `Query` itself (grep over the workspace).
8. **`InMemoryDriver` needs no change for the covered shapes**: the upsert insert is seeded from equality predicates incl. those nested in `$and`
   (`InMemoryDriver.java:7957-8013`, `:8891-8898`); once no conflicting `$setOnInsert._id` is added the insert lands under `"job"`.

## 2. Design

### 2.1 MOR-002

Marshalling happens in `Query` (only `Query` knows entity type, Morphium, mapper, helper). Not in `FindAndModifyMongoCommand`/`MongoCommand.asMap`
(`MongoCommand.java:240-280`; dumb DTOs, hand-built commands stay raw by contract), not in `BsonEncoder` (option C rejected), not in the InMemoryDriver.

1. `MorphiumObjectMapper` (`objectmapping/MorphiumObjectMapper.java`, next to `marshallIfCustomMapped` at `:56`): add `Object marshallUpdateValue(Object value);`,
   recommended as a `default` method returning `value` so external implementors do not break (only implementor in the workspace: `ObjectMapperImpl`).
2. `ObjectMapperImpl.marshallUpdateValue(Object)`, rules in order:
   - `null` returns `null`.
   - Entity or embedded POJO (`annotationHelper.isEntity(o)`, `AnnotationAndReflectionHelper.java:592-606`): at the top level of a field value `serialize(o)` without extra
     `class_name` (as `store()` `:620-623`); inside a container (List, Set, array, Map value, Map in Map) `serialize(o)` plus `class_name = getTypeId(...)` (private, `:813-833`).
   - `Enum`: `name()` (writer top level already does this, `MorphiumWriterImpl.java:2735-2737`).
   - `Collection` (not `Iterable`, because types like `java.nio.file.Path` are Iterable of themselves and the encoder only encodes `Collection`, `BsonEncoder.java:195`):
     non-List becomes `ArrayList`; a `List` is rebuilt only if an element changed (identity compare).
   - Arrays: `byte[]` and primitive arrays unchanged; other arrays become an `ArrayList` of marshalled elements.
   - `Map`: copy-on-change into `LinkedHashMap`; keys String as is, Enum becomes `name()`, anything else throws the existing `IllegalArgumentException("Can't push maps with Key not of type String!")`
     (`MorphiumWriterImpl.java:2764-2766`); values marshalled recursively in container context; value-map keys are data and never translated; `$each`, `$sort`, `$gt` are untouched.
   - Everything else (String, numbers, Date, MorphiumId, ObjectId, UUID, java.time, Pattern, custom-mapped types such as BigDecimal) returned as is. Deliberate non-goal; custom mappers belong to MOR-006.
3. Idempotency by construction: only POJO to Map and Enum to String are transformed, Maps/Lists are never re-serialised, so `marshall(marshall(x)).equals(marshall(x))`. No raw-vs-mapped flag.
4. `AnnotationAndReflectionHelper.getMongoFieldNameIfKnown(Class, String)` (new, next to `:331`): key containing `.` or `(` or starting with `$` returned unchanged; if
   `getField(realClass, key) == null` return unchanged (`getField` resolves Java name, `@Property`/`@Reference`/`@Version` name, `@Aliases`, `_id`, camelCase-converted name, `:540-580`,
   so a Mongo name resolves to itself); otherwise `getMongoFieldName(cls, key, true)`.
5. New package-private `de.caluga.morphium.query.UpdateDocumentMapper(Morphium, Class<?>)` with `Map<String,Object> map(Map<String,Object> update)`:
   - no top-level key starting with `$` (replacement document): return unchanged (auto-`$set` is MOR-013);
   - for each `$operator` whose value is a Map: new `LinkedHashMap`, key via `getMongoFieldNameIfKnown`, value via `marshallUpdateValue`;
   - element context for `$push`, `$addToSet`, `$pull`, `$pullAll`: a single POJO value is marshalled as a one-element list and unwrapped so it carries `class_name`;
   - never mutate the caller's map; nested/positional keys (`a.b`, `$`, `$[x]`) stay untranslated like `Query.set` today; `$rename` values are not translated.
6. `Query.findOneAndUpdate`, both overloads (`Query.java:432` and `:493`): map before the `try` that acquires a connection, then
   `findOneAndUpdateMapped(mapped, upsert, returnNew)` (private extraction of the existing body from `:502`: `toQueryObject`, `addGeneratedIdOnInsertIfNeeded`, command, cache clear, deserialize).
   The one-argument overload keeps its own flow and only gets the mapping step. `addGeneratedIdOnInsertIfNeeded` runs on the mapped update.
7. `MorphiumWriterImpl.marshallIfNecessary` (`:2733`): keep the public signature; top-level entity/embedded: `serialize` plus `class_name` exactly as before (`:2739-2743`);
   otherwise delegate to `morphium.getMapper().marshallUpdateValue(value)`. Fixes `Query.set`, `pushPull` (`:2674`), `pushAll` (`:2860`) for Set/array/Map-in-Map.
   Existing outputs for single/List/one-level Map stay byte-identical; difference: a null List element no longer throws NPE (`:2748`).

InMemoryDriver: no driver change; `String[]`/`Set<String>` values become Lists there (wire-equivalent to Mongo). Javadoc on both `findOneAndUpdate` overloads, the new mapper method,
`marshallIfNecessary`, `addGeneratedIdOnInsertIfNeeded`; `CHANGELOG.md` entry.

### 2.2 MOR-003

Replace `queryObject.containsKey("_id")` at `Query.java:579` by `UpsertFilterInspector.pinsId(queryObject)` (new package-private final class in `de.caluga.morphium.query`);
the `$setOnInsert._id`/`$set._id` checks (`:583-591`) stay. Rule: top level `containsKey("_id")` true (unchanged); inside `$and` (any depth) a branch pins when it has an `_id` key

(`collectUpsertEqualityFields` skips every `$or`, `:7978-7985`). Recommendation: ship `$and` now, add a probe test logging `REPRO-RESULT` for `$or` shapes, follow-up if they differ.

## 4. Risks, open questions, not verified

Behaviour changes for raw callers (list in CHANGELOG):
1. Key translation: a raw camelCase key under a translating entity is today written verbatim as a stray field (`Query.java:443`, `:517`); after the change it goes to the real field. WP5 is isolated so key translation can be dropped for a values-only variant.
2. Enums in containers and top-level `$set`: `toString()` (`BsonEncoder.java:354-357`) becomes `name()`; differs only if `toString` is overridden.

5. `@Entity` instances in updates are serialised as in the writer (`_id` kept). `@Reference` fields stored as id only (`ObjectMapperImpl.java:535-601`) need field metadata; left to MOR-006, not reproduced.

## Decisions taken in v2 (replace the matching parts above)

1. **Three PRs instead of one.**
   - **PR 1 (values + MOR-003):** probe, value marshalling in `findOneAndUpdate`, `@Reference` fail-loud, `_id` pinning, tests. No key translation, no writer change.
   - **PR 2 (key translation):** lenient resolver and operator-key mapping, own CHANGELOG entry, configuration switch.
   - **PR 3 (writer delegation):** `MorphiumWriterImpl.marshallIfNecessary` -> shared walk, with `MorphiumMigrationRunner` and the old strict `getMongoFieldName` behaviour of `Query.set` in the regression list.
2. **B1 - probe first (new WP-P).** A real-MongoDB probe runs raw `findAndModify` upserts with a deliberately different `$setOnInsert._id` and records whether the server answers code 66, for:
   `{_id:X}`, `{$and:[{_id:X}]}`, `{$and:[{_id:{$eq:X}}]}`, `{$and:[{_id:{$in:[X]}}]}`, `{$and:[{_id:{$in:[X,Y]}}]}`, `{$or:[{_id:X}]}`, `{$and:[{$or:[{_id:X}]}]}`, `{$or:[{_id:X},{_id:Y}]}`,
   `{"_id.a":1}`, `{_id:{$gt:1}}` (top level and in `$and`), `{_id:/re/}`, a collation filter, `{$and:[{_id:X},{_id:Y}]}`. `pinsId` is generated from the probe table, not from this document.
   Definition: "pins" means the server will seed `_id` from the filter, or the caller already pinned it. Narrow the MOR-003 acceptance text for every shape left out. The same matrix is run on InMem and the divergences are recorded (no InMem fix here).
3. **B2 - `@Reference`.** When the resolved target field has `@Reference` and the value is an entity, the walk must not serialise inline: store the id as the mapper's reference logic does (`ObjectMapperImpl.java:535-601`) or throw `IllegalArgumentException`. Decide in implementation by whichever is cheaper to make correct; fail-loud is the fallback. Test it either way.
4. **B3 - no alias translation, no `$rename`/`$unset` key translation.** The resolver (PR 2) resolves by Java name, `@Property`, `@Reference`, `@Version`, `_id`/`@Id` and the camelCase conversion only, never by `@Aliases`; `$rename` and `$unset` keys stay untouched. Config switch default decided with the user.
5. **M1 - reuse the stored-shape serialisers for the common case.** For `$set`/`$setOnInsert` with a resolved field (PR 2), use `serializeIterable(v, fld.getType(), fld.getGenericType())` / `serializeMap(m, fld.getGenericType())` for byte parity with `store()`. In PR 1 (no key resolution) the bespoke `marshallUpdateValue` walk is used; PR 2 may route resolved fields through the typed serialisers. Keep the walk for element operators and unknown/dotted paths.
6. **M2 - leaves.** After a byte-parity check of the encoder against the mappers for java.time and BigDecimal, route leaves through the existing `MorphiumObjectMapper.marshallIfCustomMapped` so Character, `Atomic*`, BigInteger, Timestamp and Geo types stop failing. Check `Enum` with `instanceof Enum` (enum constants with bodies).
7. **M3 - copy semantics.** Always copy containers that are handed to a command (no copy-on-no-change aliasing); test mutate-after-call on InMem. Check `MorphiumId` vs `ObjectId` equality on InMem for `$addToSet`/`$pull`; convert in the walk if the probe shows a mismatch.
8. **Interface default.** `MorphiumObjectMapper.marshallUpdateValue` is **abstract** (the only implementor in the workspace is `ObjectMapperImpl`), not a silent `default`.
9. **Test-plan additions:** concurrency (N threads, one winner, others 11000) on a real MongoDB; MorphiumId in `$addToSet`/`$pull`; `@Version` entity; `@Reference` target; `@Aliases` keys (PR 2); immutable `Map.of` input; mutate-after-call; cache read-after-update; collation upsert; `--driver all` including `SingleMongoConnectDriver`; deep equality (not `equals`) for idempotency tests with `byte[]`.
10. **New ledger items to file:** (a) `Morphium.simplifyQueryObject` `putAll` loses predicates for two `$or` branches under `$and` on the writer upsert path (`Morphium.java:1047-1065`); (b) replacement documents and `findOneAndUpdateEnums` (`Query.java:615-622`) still fail with POJOs; (c) `Expr` in `$set` still fails; (d) `$pull`/`$elemMatch` condition keys are not translated (pre-existing, document it). MOR-003 text narrowed; MOR-029 and MOR-006 text adjusted after the decisions.
