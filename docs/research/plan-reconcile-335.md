## 2. Unified design

The single source of truth is the mapper (`ObjectMapperImpl`) with two positions; only custom-mapped values differ between them.
- FIELD (whole field): `$set`, `$setOnInsert`, `$min`, `$max`, `$inc`, `$mul`, `$rename`, `set()`: a custom-mapped value is the bare M.
- ELEMENT: `push/addToSet/pull/pullAll`, the same operators in `UpdateDocumentMapper`, `$each`/`$in` members, and every container member at any depth: a custom-mapped value is `serialize(o)` (`{"value": M}` or M + class_name, mapper runs once).

API: `marshallUpdateValue(Object)` = FIELD; `marshallUpdateElement(Object)` = ELEMENT (default: marshal a singleton list, take element 0); `isCustomMapped(Class)` stays (upstream 6.3.14). Dropped: our single-value convention (no `_id` removal, no class_name omission); single entity/embedded values take element form in both positions (owner decision, matches upstream set()).
Walk order in `ObjectMapperImpl`: null, Enum (name), MorphiumId (ObjectId at all depths), Map (copy, String or enum keys, values ELEMENT), Collection/array (copy to List, members ELEMENT), entity/embedded (serialize + class_name, _id kept), `isCustomMapped(cls)` (`element ? serialize(o) : customMappers.get(cls).marshall(o)`), pass-through. Entity/embedded stays before custom-mapped (Geo keeps class_name). `UPDATE_VALUE_MAPPED_TYPES` is deleted. Keep String-key check, copying, `Class` values as data, idempotence, `$`-modifier siblings (`$position`, `$slice`, `$sort`) untouched.
Writer: `marshallIfNecessary(Object)` stays public/overridable = `mapper.marshallUpdateValue` (used by set()); new `protected marshallElement(Object)` = `mapper.marshallUpdateElement` (pushPull, pushPullAll) replaces upstream's private method; bodies of both upstream methods deleted; our eager marshalling on the calling thread stays (upstream marshals inside `WriterTask.run`).
`UpdateDocumentMapper.mapValue`: `$push/$addToSet/$pull/$pullAll` -> `marshallUpdateElement`, every other operator -> `marshallUpdateValue`. UpdateBuilder, UpdateOperations, LeaseManager, Query.modify() unchanged.

# Review outcome (challenger, dry run in /tmp/morphium-challenge) and plan v2

Verdicts: shape table mostly right but position is not a property of the operator; deleting UPDATE_VALUE_MAPPED_TYPES safe for the 8 types (BsonEncoder has no Atomic*/BigInteger/Number branch) but not for user-registered mappers; reversal of "BigDecimal/Character/Timestamp stay" agreed (upstream shipped it in 6.3.10), data-compat risk understated; the stop count (3 code + 2 ledger) confirmed; procedure and identity hygiene corrected.

Corrections taken into plan v2:
1. **Position by target path, not by operator.** `dateList.$`, `dateList.0`, `dateList.$[x]`, `dateMap.k` address one container element (store writes `{"value": M}`); `List<Object>`/`Map<String,Object>` fields write enums as `{class_name, name}`. The walk takes the declared type of the resolved target field (UpdateDocumentMapper has `type`, the writer has `cls` and `field`) and falls back to the operator default (set/$set/$inc/$min/$max/$mul/$setOnInsert = FIELD; push/addToSet/pull/pullAll/$each = ELEMENT).
2. **`$pull`/`$pullAll` conditions.** A map operand of `$pull` that is a condition (keys starting with `$`, or an embedded-field match document) must not be wrapped: `{date: LocalDate}` addresses an embedded field (bare M); `{$gte: D}` on a container of wrapped scalars can only match as `{"value": {$gte: M}}`. Upstream's `marshallElement` has the same bug (not imported knowingly): rewrite operator conditions on wrapped containers to `{"value": {...}}` or reject them with an IllegalArgumentException, and add `$in: [wrapped, flat]` for plain scalar pulls so pre-existing flat arrays are still hit.
3. **ELEMENT branch tests `mongoTypes` first** (String, Integer, Long, Float, Double, Date, Boolean, Byte, Pattern, UUID are not mapped at element/Map-value position even if a user registered a mapper for them) and only then `isCustomMapped`; at FIELD position store checks customMappers before Enum. With `useBsonDateForJavaTime` on LocalDateTime/Instant are scalars (`{"value": Date}`, no class_name).
4. **Single entity/embedded: named as accepted residual risk** (store writes class_name only for polymorph and no `_id`; update writes class_name always and keeps `_id`): a test pins it; `$pull`/`$eq`/`$addToSet` de-duplication against store()-written sub-documents can differ.
5. **Existing data:** documents written earlier by update APIs with flat list elements are read into `List<LocalDate>` as raw Longs (heap pollution, CCE at `get(0)` in user code), `$pull` misses flat elements and `$addToSet` duplicates them: CHANGELOG note is necessary, read-side tolerance test and the dual-shape `$pull` are added; the released `findOneAndUpdate(Map)` output flips from flat to wrapped (superseding Unreleased "Changed" entry; the released 6.3.14 text is not edited).
6. **BigDecimal/Timestamp:** BsonEncoder writes BigDecimal as Decimal128 today; after the change a lossy double (as upstream shipped), Timestamp Date -> long; `$inc/$min/$max` with BigDecimal on an existing Decimal128 field is a new mixed-type path: explicit owner acceptance needed.
7. **Mechanics:** one `git rebase --rebase-merges --update-refs --onto origin/develop d2cc4c5bf` (keeps the diamond merge, gave exactly the 3 code + 2 ledger stops; 6836bac4b is not a conflict but a semantic edit); fold R1 (two-position walk) into the first commit that touches the area (562b5b31e / b07b1f8a3) so no PR is red against develop's `CustomMapperUpdateShapeTest`; set the local git identity (`user.email heiko@kopp-cloud.de`, committer too) BEFORE rebasing and verify `%ae %ce` afterwards; no Co-authored-by; rerere cache of the trial is not reused; additive conflicts resolved by hand (a naive union drops braces/Javadoc openers; keep upstream's and our settings non-transient).

9. **Lineages:** the published (scrubbed, rebased) lineage becomes canonical. Local branches (original lineage) are replaced by it; the local-only work on top of feat/mor-059 (coverage-gaps, MOR-064) is moved with `git rebase --onto` afterwards. Uncommitted MOR-064 changes are committed first.
